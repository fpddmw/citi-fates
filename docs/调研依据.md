# 调研依据

- 整理日期：2026-09-26。
- 范围：本轮已查阅的相邻游戏、原始研究和官方工具资料。
- 用途：支持技术方向与设计判断，不将相邻作品的玩法照搬为本作方案。

动态网页和模型资料会更新。实施时应重新固定具体版本、文件与运行环境。这里的“提供能力”指来源所描述的组件或实验，不代表本项目已经验证。

## 1. 相邻游戏与讨论结论

| 来源 | 与本作相关的内容 | 本轮得到的设计问题 |
|---|---|---|
| [Magicmaker 官方商店页](https://store.steampowered.com/app/319250/Magicmaker/) | 通过具有既定作用的材料组合魔法 | 可组合性本身可以由规则实现；模型增量要进一步体现词义关系构造 |
| [Noita 官方商店页](https://store.steampowered.com/app/881100/Noita/) | 法术组合与环境模拟形成多种相互作用 | 学习所得如何迁移、怎样让玩家较早发现构筑空间，值得关注 |
| [Magicraft 官方商店页](https://store.steampowered.com/app/2103140/Magicraft/) | Roguelike 战斗与法术组合 | 效果规模扩大后，战斗可读性仍需作为核心条件 |
| [Spellmasons 官方商店页](https://store.steampowered.com/app/1618380/Spellmasons/) | 回合制场景中组合施法与目标关系 | 作用顺序、对象和空间关系可以形成深度，不只依赖数量与数值 |
| [Magicka 官方介绍](https://www.paradoxinteractive.com/games/magicka/about) | 元素组合形成魔法 | 元素融合与组合已有先例，本作需明确日常语义和自主构造的差异 |
| [Mages of Mystralia 官方商店页](https://store.steampowered.com/app/529660/Mages_of_Mystralia/) | 符文组合与能力运用 | 符文载体不自动意味着需要语言模型 |
| [Infinite Craft 官方页面](https://neal.fun/infinite-craft/) | 持续组合发现新元素 | 新词发现可以产生探索欲，本作还要求新词落实为战斗能力 |
| [AI Spelcraft 官方商店页](https://store.steampowered.com/app/3622760/AI_Spelcraft/) | 文字组合与 AI 法术评价／生成方向 | 文字生成与可执行行为、完整演出的能力需分别评价 |

用户未采用将上述游戏的既有结构直接拼接为本作核心玩法的提案。当前方向由稳定真实词义、精灵定向融合、法杖装配、位阶成长与整体关系生成构成。

本轮曾讨论这些作品的知名度。已查阅的 Steam 页面显示部分作品有较大评论规模，“这些游戏都不出名”不作为事实前提。评论数量、语言范围、上线时间与销量分别统计，本稿不据此推定商业成败或原因。

关于效果遮挡，曾查阅 [Magicraft 玩家讨论](https://steamcommunity.com/app/2103140/discussions/0/595137684887900572/)。关于学习体验，曾查阅 [Noita 玩家评论](https://steamcommunity.com/app/881100/reviews/?browsefilter=toprated&l=english)。这些是个体反馈，帮助形成可读性、上手发现和知识迁移的测试问题；它们不代表完整用户群体或销量归因。

## 2. 原始研究与技术组件

### T01：可执行技能生成

[Generate Diverse Skills with Large Language Models，FDG 2026](https://www.pcgworkshop.com/archive/xu2026infinite.pdf)

研究使用本地 Llama 3.1 8B 与 Qwen2.5 14B，将元素布局转换为限定结构中的技能。实验比较规则、模板、随机和模型等条件，涉及 105 种配置、11 类动作与 11 类修饰，报告了元素一致性与生成多样性方面的结果。

其输入与执行空间较固定，评估包含文本和结构指标；玩家控制感与满意度列为后续研究。它支持受约束语义生成的实验路径，本作更丰富的中文词义、本地小模型表现和实际乐趣仍需独立验证。

### T02：整体粒子效果生成

[ParticleGen: A Multi-Agent System for Particle Effects Generation，2026](https://arxiv.org/html/2608.00629v1)

研究依据模块知识与素材库生成结构化粒子系统，转换成 UE5 Niagara 资源，再用渲染反馈修正。实验使用 GPT-5.4 等较强模型，配置 35 类行为模块和 21 个素材，测试描述位于素材库表达范围内。

它展示了从整体规划到参数与反馈的流程，也说明预设原料可以支持不同组织方式。本文借鉴其方法，尚未证明本地 2B／4B 模型或本项目客户端能取得相同质量与等待时间。

### T03：本地语言模型候选

- [Qwen3.5-4B 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-4B)
- [Qwen3.5-2B 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-2B)
- [Qwen3-1.7B 官方模型卡](https://huggingface.co/Qwen/Qwen3-1.7B)

候选承接用户技术方案。模型卡提供结构、使用方式及权重信息，不包含本项目词义构造、融合消耗、整体演出和实战测试结果。当前尚未下载、部署、量化比较或训练。

### T04：本地推理与结构约束

- [llama.cpp 官方仓库](https://github.com/ggml-org/llama.cpp)
- [语法与 JSON Schema 支持说明](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md)

提供本地推理和结构约束路径。普通结构约束中的 schema 不会自动成为模型可见提示，且转换支持范围有限；使用时需同时提供接口说明与独立校验。结构合法、语义正确和游戏可用分别测试。

### T05：引擎中的程序化表现

- [Godot ParticleProcessMaterial](https://docs.godotengine.org/en/stable/classes/class_particleprocessmaterial.html)
- [Godot NoiseTexture2D](https://docs.godotengine.org/en/stable/classes/class_noisetexture2d.html)
- [Godot 使用 SubViewport 作为纹理](https://docs.godotengine.org/en/stable/tutorials/shaders/using_viewport_as_texture.html)

这些接口提供粒子参数、噪声纹理与渲染到纹理的基础能力。整体行为与视觉共享结构、动态资源加载、导出包兼容及性能仍需项目实现和测试。Godot 与 Unity 仍是候选，未进行最终选型。

### T06：美术原料生成候选

[FLUX.2 klein 4B 官方模型卡](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B)

支持图像生成与编辑，官方给出约 13GB 显存的运行配置说明，可作为用户提供的 4090 环境中的测试候选。具体峰值与速度依赖实现与设置，官方数字不作本项目性能承诺。

本作还需验证透明通道、轮廓、缩小效果、风格一致和后处理工作量。能够生成图片不自动等于能够直接交付合格粒子素材或动画。

### T07：本地目录与实例存储

- [SQLite 适用场景](https://www.sqlite.org/whentouse.html)
- [SQLite WAL](https://www.sqlite.org/wal.html)

可作为本地内容目录、应用数据和缓存的候选。事务策略、素材文件依赖、取消恢复及更新迁移由项目具体设计；数据库和外部文件的完整性需要共同处理。

### T08：组合空间与仿真评价

[Exploring the Possibility Space of 1 Billion Spells，2025](https://www.pcgworkshop.com/archive/withington2025spells.pdf)

以节点法术及简化仿真分析组合空间，为自动评价提供方法参照。其命中和触发假设简化了真实战斗条件，本作仍需在实际敌人、空间、时序和跨技能作用中检验结果。

### T09：后续参数高效适配

[Hugging Face PEFT 量化与适配文档](https://huggingface.co/docs/peft/main/en/developer_guides/quantization)

提供量化模型适配的技术参考。具体训练方案、数据、显存需求及收益尚未确定；单卡容器可用不直接推出需要训练，适配后的推理质量和速度需重新测量。

## 3. 研究判断如何进入策划

当前支持继续验证的方向是：稳定词义资料与可组合能力结合，模型组织整体结构，程序执行并反馈，已有素材参与可编辑演出。

需要本项目回答的核心问题是：对未预写组合是否形成合理关系、玩家意图是否被兑现、行为与演出是否一致、玩家能否理解和使用，以及本地等待和资源成本是否合适。

研究记录、官方说明和模型卡支持组件能力及实验方法。主策划中的新玩法、词义映射、位阶和平衡仍分别保留用户方向、建议或待验证状态。
