## 2. 最新决定之间的关系

### 2.1 提示词与稳定词义

D12 约束玩家不编辑词义；D14 允许玩家向精灵表达融合方向。两者共同成立：提示影响候选、材料选择和用途，符文的定义保持稳定。

不将这一更新理解为重新允许自由改写词语，或将聊天提示扩展到全部游戏交互。

### 2.2 融合与法杖装配

精灵融合产生新符文，并按实际参与材料处理消耗与返还；法杖使用符文组合形成技能。一次技能构造不自动产生一批可领取的符文。

模型完成两个任务所需的调用方式、方案复用和缓存仍为技术设计问题。玩家端保留这两个操作的清楚含义。

### 2.3 探索与稳定构筑

被明确取消的是“留空自动补全”机制。仍保留词语关系发现、定向融合、实际战斗学习与构筑积累。未知符文辨识是尚未决定的独立候选。

稳定的是词义和已确认技能实例；相同词语在不同组合中能够形成不同应用。全局唯一配方、同组合跨玩家差异、重装复用和重新生成机会尚未全部决定。

### 2.4 模型与预生成

讨论曾认为离线生产可作为基线。随后用户加入精灵提示，并明确继续研究自主关系构造，因此当前目标包含本地模型处理未逐项预设的语义组合。

预设素材、受限接口与程序执行继续有效。把所有完整技能或关系预先写好、模型只做选择，属于较小的后备范围，需要明确其体验差距。

## 3. 已撤回与未获确认的方案

| 内容 | 当前处理 |
|---|---|
| 以独立工作台作为游戏主体 | 已否定；页面服务于 Roguelike 战斗 |
| 生造词条和强行起新名称 | 已否定；词条需有真实稳定含义 |
| 填满＝定制、留空＝探索 | 用户明确撤回，替换为精灵融合 |
| 玩家编辑词义 | 已否定；通过组合与融合意图表达 |
| 神圣固定白色／图案、词条固定运动 | 已否定为设计原则；具体技能可有具体美术，但不绑定词义 |
| 每个词分别贡献一层独立特效 | 不满足当前核心目标 |
| 预设培养、共鸣菜单与固定线性成长链 | 未采用；不作为本作既定成长体系 |
| 两项技能、每次两三个词、完整六类槽位 | 助手说明性参数，未定案 |
| 任意词条都可直接输入并获得 | 未获授权；当前提示用于精灵融合方向 |
| 每个组合必须产出新词、每次融合必升阶 | 未决定 |
| 更抽象的词必然更强、相反词必定高稀有 | 尚未形成有效规则 |
| 运行时模型已被取消 | 不符合最新方向，继续研究 |
| 本地模型已证明好用、训练必需 | 尚无本项目实测 |

本节中的排除记录只用于防止讨论回退，不把这些旧方案并列为当前可选玩法。
